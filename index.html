Proyecto: Análisis de Retención E-commerce

Construyendo un Pipeline End-to-End

1. Data Foundry: Extracción y Normalización

Aprende a cruzar tablas y extraer métricas maestras utilizando las herramientas corporativas de SQL.

Data Wrangling Orientado a Churn

El "Data Wrangling" (o doma de datos) es el proceso fundamental de transformar datos crudos y dispersos en un formato estructurado y analizable. En el contexto del E-Commerce Churn, la meta es crear un "Dataset Plano" (flattened dataset) donde cada fila represente un cliente único, concatenado a la totalidad de su historial transaccional y métricas de inactividad.

La Defensa del LEFT JOIN

¿Por qué LEFT JOIN es sagrado en el análisis de retención? Imagina que realizas un INNER JOIN clásico entre la tabla Customers (todos los registrados) y la tabla Orders (las transacciones facturadas). El motor SQL interceptará las llaves y destruirá (omitirá) inmediatamente a todos los clientes que se registraron pero que nunca compraron nada. Al perder esos registros, pierdes la visibilidad entera del 'Early Churn' (usuarios que rebotan sin generar ganancias). Con LEFT JOIN garantizas que tu tabla madre dictamine la integridad del ecosistema de datos, manteniendo los perfiles intactos y rellenando con valores NULL aquellas áreas sin facturación, las cuales más tarde el Analytic Engine de Python utilizará como poderosas banderas para sus algoritmos predictivos.

-- Ejemplo de una extracción segura para un data pipeline.
SELECT c.customer_id, 
       c.signup_date,
       o.order_date, 
       o.total_amount
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id;

2. Analytic Engine: Python & Pandas

Limpia vectores nulos y construye un modelo de categorización RFM puro.

Anatomía del Modelo Predictivo RFM

En la ingesta de Machine Learning, el modelo de Segmentación RFM (Recency, Frequency, Monetary) actúa como un radar forense sobre el comportamiento del usuario. Es una de las metodologías cuantitativas más implacables y certeras.

De las tres variables, la Recencia (Recency) es el predictor absoluto supremo para detectar el Churn. La Recencia responde a una pregunta matemática sencilla: ¿Hace cuántos días ocurrió el último latido financiero (transacción) del cliente?. La teoría indica que la probabilidad del usuario para generar una nueva compra cae exponencialmente según aumenten los días inactivos. Si un cliente tenía una alta Frecuencia (F) y un Monetary Value alto (M), pero su Recencia actual supera drásticamente su tiempo promedio de recompra, estamos ante un caso claro de fuga (Churn) VIP inminente.

El Rol de Pandas en el Engine Analítico

La inyección de los datos brutos provenientes de SQL necesita una curaduría refinada. Los vectores NULL dejados sistemáticamente por los LEFT JOIN no son vacíos accidentales: son valiosa información de no-ingreso. Mediante el poder de la librería `pandas`, imputamos o llenamos (`fillna()`) esos campos para normalizar el tensor de entrada de los algoritmos e impedir rupturas de compilación en el eventual clasificador entrenado con `Scikit-Learn`.

import pandas as pd
import numpy as np

# Ingesta
df = pd.read_csv('datasets_ejemplo.csv')

# Ingeniería del Modelo RFM - Cálculo de Recencia Matemática
# (Usando una fecha de corte simulada)
corte_tiempo = pd.to_datetime('2025-01-01')

rfm_engine = df.groupby('customer_id').agg({
    'last_purchase_date': lambda x: (corte_tiempo - pd.to_datetime(x.max())).days,
    'order_id': 'count',
    'total_spent': 'sum'
}).rename(columns={
    'last_purchase_date': 'Recency',
    'order_id': 'Frequency',
    'total_spent': 'Monetary'
})

print(rfm_engine.sort_values(by="Recency", ascending=False).head())

3. Executive Front-end: Dashboards Reales

Presenta los insights procesados en una interfaz que los tomadores de decisiones entiendan.

Storytelling con Datos (El Rol Ejecutivo)

El código más avanzado del mundo no tiene ningún impacto si el CEO de tu compañía no logra asimilar la urgencia de la información. Excel y Power BI encarnan el 'Executive Front-End', donde la rigurosidad matemática se transforma en **Storytelling Técnico**.

Focalización a través de la Paleta de Colores

Diseñar un Dashboard no es pintar de colores variopintos una gráfica; es dirigir el ojo del ejecutivo hacia la decisión. La semiótica (el uso del color) en el cálculo de Retention Rate sigue un principio biológico de urgencia:

  • Alerta Crítica (Rojos/Carmesí): Se destinan visualmente a los KPIs representativos de clientes desertores (Churn alto). Inmediatamente inyectan la sensación de peligro financiero o fuga de ingresos.
  • Validación Positiva (Verdes/Esmeralda): Reservados exclusivamente para las cohortes de clientes que se han retenido, destacando el LTV (Life Time Value) positivo y confirmando la lealtad con seguridad táctica.
  • Información Neutral (Grises/Azules oscuros): Constituyen el fondo y las tablas base de lectura de tendencias, nunca desvían la atención ni cansan la vista del Directivo (Dark Mode UX).

Automatización Escalable con Power Query
